# Proxy

Автоматически обновляемый список публичных MTProto-прокси для Telegram.
Раз в 2 часа GitHub Actions собирает ссылки из каналов (`channels.txt`),
проверяет, что хосты живы, и публикует результат.

> Проверка здесь **глобальная** (TCP-подключение с серверов GitHub): она отсеивает
> мёртвые хосты, но не гарантирует, что прокси работает у вас в стране.
> Окончательную проверку должен делать клиент.

## Файлы

| Файл | Назначение |
|---|---|
| `proxies.json` | Список для клиентов, отсортирован по пингу |
| `proxyes.txt` | Те же прокси ссылками `https://t.me/proxy?...` |
| `state.json` | Внутренняя история проверок (клиентам не нужен) |
| `channels.txt` | Каналы-источники |

## Формат `proxies.json`

```json
{
  "updated": "2026-11-25T22:00Z",
  "count": 120,
  "proxies": [
    {
      "server": "1.2.3.4",
      "port": 443,
      "secret": "ee…",
      "type": "fake-tls",
      "domain": "example.com",
      "ping_ms": 40,
      "first_seen": "2026-11-25T12:00Z",
      "last_ok": "2026-11-25T22:00Z"
    }
  ]
}
```

- `secret` всегда в hex, его можно подставлять прямо в `tg://proxy?...&secret=`.
- `type`: `fake-tls` (`ee`), `padded` (`dd`) или `simple`.
- `ping_ms` — пинг от раннера GitHub, не от пользователя; используйте только для порядка.

## Рекомендации клиенту

1. Скачать `proxies.json` (raw.githubusercontent.com, запасное зеркало — jsDelivr).
2. Взять первые N записей, проверить реальное подключение через прокси с коротким таймаутом.
3. Запомнить рабочий, при сбое переключиться на следующий; держать в приложении резервный список.
